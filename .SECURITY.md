# MoreAI Security Considerations

## AI Security

### Prompt Injection Defense
Every agent input is scanned against known injection patterns before processing:
- "ignore previous instructions"
- "you are now", "pretend you", "act as"
- "jailbreak", "bypass safety", "DAN mode"

Blocked requests return HTTP 400 and are logged in the audit trail.

**Test cases verified:**
### PII Redaction
All agent outputs pass through Microsoft Presidio before leaving the system.
Detected and redacted entities: EMAIL, PHONE_NUMBER, PERSON, LOCATION,
CREDIT_CARD, SSN, IP_ADDRESS, US_BANK_NUMBER.

### Output Filtering
Agent outputs are filtered for PII before every API response.

## API Security

### Authentication
- JWT tokens (HS256) with 30-minute expiry
- bcrypt password hashing (cost factor 12)
- Tokens never stored server-side — stateless auth

### RBAC — Role-Based Access Control
| Role | Permissions |
|------|------------|
| Admin | All operations + user management + audit logs |
| Developer | Run agents, eval, RAG read/write, registry read |
| Viewer | Read-only access to agents, eval, RAG, registry |

### Rate Limiting
10 requests per minute per IP address.
Returns HTTP 429 on breach.

### Secrets Management
- All secrets loaded from environment variables
- Never hardcoded in source code
- `.env` in `.gitignore` — never committed
- CI uses GitHub Secrets — never plaintext in workflow files
- AWS S3 server-side encryption (AES256) on all artifacts

## RAG Security

### Document Isolation
Every ingested document is tagged with the user's ID.
Retrieval is scoped to the calling user's documents by default.
Cross-user retrieval is explicitly blocked unless admin.

### Source Verification
Documents are stored with source metadata.
Retrieved context always includes source attribution.

### Citation Grounding
Agent outputs that use RAG context include source references.
This prevents hallucination from being attributed to real documents.

## DevOps Security

### GitHub Secrets
All sensitive values in CI are stored as GitHub Actions secrets:
- Never visible in logs
- Never in workflow YAML files
- Scoped to repository only

### Docker Security
- Non-root user in container (planned)
- No secrets baked into Docker image
- `.dockerignore` excludes `.env` and credentials

### Dependency Scanning
```bash
pip audit                    # Python CVE scanning
npm audit                    # Node.js CVE scanning
```

### Audit Logging
Every sensitive action is logged to `audit_log.jsonl`:
- User registration and login
- Every agent run (user, task preview, IP, timestamp)
- Prompt injection blocks
- Pipeline approvals and rejections
- Deployment events

## Known Limitations

1. In-memory user store — restart clears all users (swap for PostgreSQL in production)
2. ChromaDB persistence — works locally, needs EBS volume in K8s
3. Presidio fallback — if Presidio is not installed, PII redaction is skipped with a warning
4. Rate limiting is IP-based — can be bypassed with proxies (add token-based limiting for production)
